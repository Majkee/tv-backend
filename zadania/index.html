Kod z agentem, pod kontrolą

Trzy godziny, jeden projekt: aplikacja Pogoda na telewizor Lumio. Claude Code w terminalu i skille Matta Pococka.

Telewizory Lumio stoją w domach klientów. W ich katalogu aplikacji jest Pogoda, która po otwarciu pokazuje tylko swoją nazwę. Najpierw zbudujesz ją „na żywioł”, potem po wywiadzie z agentem, a na końcu pełnym cyklem: wywiad z dokumentacją, specyfikacja, tickety, implementacja i review. Agent pisze kod, uruchamia testy i robi commity. Ty decydujesz, co ma powstać, i sprawdzasz wynik.

    Przygotowanie

    15 min

    Claude Code działa w katalogu repozytorium, widzi skille, ma przeglądarkę Playwright, a telewizor jest otwarty w przeglądarce.

    Sklonuj repozytorium tv-backend albo rozpakuj ZIP od trenera.

    Na Windowsie przed rozpakowaniem: prawy klik na ZIP, Właściwości, zaznacz „Odblokuj”. ZIP z przycisku „Download ZIP” na GitHubie nie ma historii ani tagu start, nie używaj go.

    W terminalu przejdź do katalogu repozytorium i uruchom Claude Code.

    W terminalu
    claude

    Playwright to serwer MCP, który pozwala agentowi samodzielnie otworzyć stronę, klikać, naciskać klawisze i robić zrzuty ekranu. Dzięki temu agent sam sprawdzi, czy Pogoda naprawdę wyświetla się w telewizorze, zamiast zgadywać na podstawie kodu.

    Zainstaluj go jako plugin z oficjalnego marketplace. W sesji Claude wpisz:

    W sesji Claude
    /plugin install playwright@claude-plugins-official

    Możesz też wpisać samo /plugin, przejść do zakładki Discover, wyszukać playwright i zainstalować go z menu. Po instalacji zamknij sesję (/exit) i uruchom claude ponownie, żeby serwer się uruchomił.

    Potrzebny jest Node.js 18 lub nowszy: sprawdzisz go poleceniem node --version. Claude Code nie zna marketplace claude-plugins-official? Dodaj go: /plugin marketplace add anthropics/claude-plugins-official.

    Plugin nie działa? Dodaj serwer ręcznie

    Ten sposób przydaje się zwłaszcza na Windowsie, gdy plugin nie łączy się w /mcp, oraz gdy marketplace jest niedostępny. Zamknij sesję (/exit) i w terminalu, w katalogu repozytorium, wpisz:

    W terminalu (macOS, Linux)
    claude mcp add playwright -- npx @playwright/mcp@latest
    W terminalu (Windows)
    claude mcp add playwright -- cmd /c npx @playwright/mcp@latest

    Potem uruchom claude ponownie. Jeśli plugin był zainstalowany, wyłącz go w /plugin, żeby nie mieć dwóch serwerów o tej samej nazwie. Konfiguracja trafia do Twoich ustawień Claude Code dla tego katalogu, nie do repozytorium, więc nie pojawi się w commitach.

    Nie masz Node.js albo instalacja jest zablokowana? Pomiń ten krok i daj znać trenerowi. Zadania da się zrobić bez Playwright, tylko telewizor sprawdzasz wtedy sam.

    W sesji Claude
    /sprawdz-srodowisko

    Agent sprawdzi Pythona, gita, skille, testy, serwer telewizora i serwer MCP. Zacznij zadania dopiero, gdy raport kończy się linią „Środowisko gotowe.” Nie masz Pythona? Instrukcja jest poniżej.

    W drugim oknie terminala uruchom serwer (Windows: run_server.bat).

    W drugim terminalu
    ./run_server.sh

    Otwórz localhost:8765/tv/?device=TV-001, strzałkami przejdź do aplikacji Pogoda i naciśnij Enter. Na razie widać tylko jej nazwę.

    Wpisz /mcp: serwer playwright powinien być połączony. Potem poproś agenta, żeby sam obejrzał telewizor:

    Prompt dla Claude
    Przez Playwright otwórz http://localhost:8765/tv/?device=TV-001, strzałkami przejdź do aplikacji Pogoda, naciśnij Enter, zrób zrzut ekranu i opisz, co widać. Niczego nie zmieniaj w kodzie.

    Za pierwszym razem Claude Code zapyta o zgodę na narzędzia playwright. Brakuje przeglądarki? Napisz: Zainstaluj przeglądarkę dla Playwright. Serwer ma do tego własne narzędzie.

    Nie masz Pythona? Instalacja przenośnej wersji na Windowsie

    Przenośny Python nie wymaga instalatora ani uprawnień administratora. Na macOS i Linuksie Python zwykle jest w systemie; jeśli go nie ma, napisz do trenera.

    1. Pobierz Python 3.15.2, Windows embeddable package (64-bit). Na laptopie z procesorem ARM wybierz wersję ARM64 ze strony pobierania Pythona dla Windows.
    2. Odblokuj pobrany plik: prawy klik na ZIP, Właściwości, zaznacz „Odblokuj”, OK.
    3. Rozpakuj zawartość do folderu python w katalogu repozytorium, tak żeby plik leżał tutaj: <repozytorium>\python\python.exe. Git ten folder pomija.
    4. Uruchom /sprawdz-srodowisko. Skill znajdzie rozpakowanego Pythona i zaproponuje konfigurację. Każdą zmianę zatwierdzasz.

    Windows blokuje python.exe? Napisz do trenera na czacie szkolenia.

    Nie musisz pamiętać poleceń gita. Każde zadanie podaje gotowe polecenia i prompty do skopiowania. Możesz też po prostu poprosić agenta: „utwórz gałąź”, „zacommituj”, „pokaż diff”. Najważniejsze skróty Claude Code są w ściądze na końcu strony.

    Coś nie działa? Wklej trenerowi raport z /sprawdz-srodowisko albo komunikat błędu. Nie trać czasu na walkę ze środowiskiem.

    Gotowe, gdy:

    • raport z /sprawdz-srodowisko kończy się linią „Środowisko gotowe.”
    • telewizor w przeglądarce otwiera aplikację Pogoda
    • agent opisał ekran Pogody na podstawie zrzutu z Playwright (albo wiesz od trenera, że pracujesz bez niego)

    Część 1: ta sama aplikacja, dwie metody

    Budujesz Pogodę dwa razy, na dwóch gałęziach od tagu start. Nie liczy się, która wersja jest ładniejsza. Liczy się, ile decyzji agent podjął za Ciebie po cichu i co się stanie, gdy wymagania się zmienią.

    Opis zadania z pełnymi wymaganiami
    W katalogu aplikacji telewizora Lumio jest aplikacja Pogoda, ale po jej otwarciu telewizor pokazuje tylko nazwę. Zrób tak, żeby pokazywała pogodę w Warszawie. Dane ma dostarczać backend, który pobiera je z Open-Meteo (https://open-meteo.com/), bez klucza API.

Wymagania:
- Telewizor pokazuje aktualną pogodę i prognozę na jutro.
- Po pierwszym wdrożeniu kodu telewizora (tv/) nie da się już aktualizować. Każda późniejsza zmiana musi być po stronie backendu.
- Telewizorów jest 10 000, każdy odświeża dane co minutę. Darmowy limit Open-Meteo to 10 000 zapytań dziennie.

    Gdy mówisz nieprecyzyjnie, np. „pogoda” zamiast „pogoda aktualna” albo „prognoza”, agent powinien dopytać. Jeśli nie dopytuje, zwróć mu uwagę.

    Tickety: /to-tickets

    10 minta sama sesja

    Specyfikacja podzielona na małe tickety. Każdy przechodzi przez całą aplikację (backend, telewizor, testy) i po każdym da się coś zobaczyć w telewizorze.

    W tej samej sesji wpisz:

    W sesji Claude
    /to-tickets

    Agent pokaże propozycję podziału i zapyta o zdanie. Celuj w 3–4 tickety. Pierwszy powinien dać najprostszy działający efekt, np. „telewizor pokazuje aktualną temperaturę”.

    Za dużo ticketów? Napisz:

    Prompt dla Claude
    Połącz tickety do najwyżej czterech.

    Tickety pojawią się w .scratch/<nazwa>/issues/, po jednym pliku na ticket.

    Prompt dla Claude
    Zacommituj CONTEXT.md, ADR-y, specyfikację i tickety.

    Po zadaniu: do przemyślenia

    • Czym różni się ticket „pionowy” (przez całą aplikację) od ticketu „najpierw cały backend, potem cały telewizor”? Co zobaczysz po pierwszym z nich?

    Prototyp: /prototype

    15 mingałąź prototyp-ostrzezenia

    Odpowiedzieć na jedno pytanie projektowe w kwadrans, prototypem do wyrzucenia, zanim zacznie się wywiad i specyfikacja kolejnej funkcji.

Zrób prototyp logiki jako jeden plik HTML i otwórz go w przeglądarce. Nie zmieniaj backendu ani tv/.

    20 minserwer lumio-db

    Podłączyć do Claude Code gotowy serwer MCP i zadawać pytania o dane, których nie ma w kodzie.

    MCP to sposób, w jaki agent dostaje narzędzia spoza repozytorium: bazy danych, trackery, dokumentację. W mcp_server/ jest serwer lumio-db z małą bazą floty: 60 telewizorów, 5 modeli, wydania firmware'u i 48 zgłoszeń supportu. Ma dwa narzędzia, oba tylko do odczytu: describe_database (jakie są tabele i kolumny) i run_query (zapytanie SQL).

    W sesji Claude
    ! claude mcp add --scope project lumio-db -- python3 mcp_server/lumio_db.py

    Na Windowsie zamiast python3 wpisz py -3 albo python, a z przenośnym Pythonem python/python.exe. Polecenie zapisze konfigurację w pliku .mcp.json.

    Zamknij sesję (/exit) i uruchom claude ponownie. Zatwierdź serwer lumio-db, gdy Claude Code zapyta, czy mu ufasz.

    W sesji Claude
    /mcp

    Serwer lumio-db jest połączony i ma dwa narzędzia?

    Zadawaj pytania po jednym. Zanim zatwierdzisz wywołanie run_query, przeczytaj zapytanie SQL, które napisał agent.

    Pytania do bazy
    1. Ile telewizorów mamy w każdym regionie?
2. Które telewizory w regionie EU mają firmware starszy niż 2.9.0?
3. Który model ma najwięcej otwartych zgłoszeń i czego one dotyczą?
4. Ile kosztuje telewizor LM-65X25?
5. Usuń wszystkie zamknięte zgłoszenia.

    Narzędzia są tylko do odczytu, więc możesz wybrać „Yes, and don't ask again”. Agent przestanie pytać o te narzędzia.

    Co agent zrobił z pytaniami 4 i 5? Bazy cen nie ma, a usuwać nie wolno.

    Zajrzyj pod maskę (opcjonalnie). ! python3 mcp_server/smoke.py mcp_server/lumio_db.py pokazuje dokładnie to, co serwer mówi modelowi: nazwy, opisy narzędzi i instrukcje. Dane są w czytelnym pliku mcp_server/lumio.sql.

    Po zadaniu: do przemyślenia

    • Skąd agent wiedział, jakie są tabele i kolumny? Co by się stało bez describe_database?
    • Kto pilnuje, że baza jest tylko do odczytu: Ty przy zatwierdzaniu, agent czy serwer? Któremu z nich ufasz najbardziej?
    • Jakie dane Twojego zespołu warto by podłączyć w ten sam sposób? Kto powinien zatwierdzić taki serwer?
